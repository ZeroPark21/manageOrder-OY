# 하드코딩 문제 반성문 및 개선 방안

## 🚨 발생한 문제

### 문제 상황
- **발생 일시**: 2025년 9월 10일
- **발생 위치**: `app/page.tsx` 라인 304
- **문제 내용**: 샘플 발송 현황 페이지에서 총 샘플 발송 개수가 하드코딩되어 있음

### 구체적 문제점
```typescript
// 문제가 된 하드코딩
<div className="text-2xl font-bold">2,106개</div>
<p className="text-xs text-muted-foreground">주문 2,106건</p>
```

- **하드코딩된 값**: 2,106개
- **실제 API 데이터**: 2,229개 (123개 차이)
- **사용자 혼란**: 같은 페이지에서 서로 다른 총합 수치 표시

## 🔍 문제 원인 분석

### 1. 데이터 일관성 부재
- UI에 표시되는 요약 카드는 하드코딩된 값 사용
- 월별 매트릭스는 `/api/all-matrix` API에서 실제 데이터 조회
- 동일한 데이터 소스를 사용하지 않아 불일치 발생

### 2. 개발 프로세스 문제
- 초기 개발 시 임시 값으로 하드코딩
- 실제 API 연동 시 하드코딩된 값 업데이트 누락
- 코드 리뷰 과정에서 하드코딩 검증 부족

### 3. 유지보수성 저하
- 데이터 변경 시 여러 곳을 수동으로 업데이트해야 함
- 휴먼 에러 발생 가능성 증가
- 테스트 환경과 프로덕션 환경 간 데이터 불일치 위험

## 🚫 절대 금지 사항

### 하드코딩 금지 대상
1. **숫자 데이터**
   - 통계 수치, 카운트, 합계, 평균 등 모든 계산된 값
   - 날짜별, 월별, 연별 집계 데이터
   - 사용자 수, 주문 수, 매출액 등 비즈니스 메트릭

2. **동적 텍스트**
   - 상태 메시지, 알림 문구
   - 사용자명, 제품명 등 변동 가능한 텍스트

3. **설정 값**
   - API 엔드포인트, 환경별 설정
   - 임계값, 제한값 등 비즈니스 로직 관련 수치

## ✅ 올바른 구현 방법

### 1. API 우선 원칙
```typescript
// ❌ 잘못된 방법 (하드코딩)
<div className="text-2xl font-bold">2,106개</div>

// ✅ 올바른 방법 (API 데이터 사용)
<div className="text-2xl font-bold">{summaryData?.totalCount?.toLocaleString() || 0}개</div>
```

### 2. 상태 관리
```typescript

  cancelledCount: number;
  shippedCount: number;
}

```

- 데이터 동기화 보장
