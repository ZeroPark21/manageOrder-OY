# Claude Code Rules

## 1. 기존 코드 우선 활용 원칙
- **항상 기존 코드를 먼저 확인하고 최대한 활용한다**
- 파라미터나 파일명만 변경하면 되는 경우 새 파일을 만들지 않는다
- 새로운 기능이나 분석이 필요할 때는 기존 파일을 확장하거나 수정한다
- 기존 코드의 구조와 패턴을 유지하며 일관성을 보장한다

## 2. 기존 코드 수정 시 원칙
- **수정이 필요할 때는 기존 코드 파일 내에서 수정한다**
- 새 파일을 만들기보다는 기존 파일에 기능을 추가하거나 개선한다
- 수정 시 기존 기능을 손상시키지 않도록 주의한다
- 코드 히스토리를 파일 내 주석으로 기록한다

## 3. 새 파일 생성 시 허가 요청 규칙
새로운 코드 파일을 생성하기 전에 반드시 다음 정보와 함께 허가를 요청해야 한다:

### 요청해야 할 정보:
1. **새 파일을 만들어야 하는 이유**
   - 기존 코드로는 해결할 수 없는 구체적인 이유
   - 새로운 기능의 필요성
   - 코드 분리가 필요한 논리적 근거

2. **기존 코드가 필요없어진 이유** (해당하는 경우)
   - 기존 코드의 한계점
   - 더 이상 사용되지 않는 이유
   - 대체되어야 하는 구체적인 문제점

3. **제안하는 파일명과 목적**
   - 새 파일의 명확한 역할
   - 기존 파일과의 관계성

### 허가 요청 형식:
```
새 파일 생성 허가 요청:

파일명: [제안하는 파일명]
목적: [파일의 역할과 기능]

새 파일이 필요한 이유:
- [구체적인 이유 1]
- [구체적인 이유 2]

기존 코드 대신 새 파일이 필요한 이유:
- [기존 코드의 한계점]
- [새 파일로 해결되는 문제점]

허가해주시겠습니까?
```

## 4. 새 파일 생성 시 문서화 의무
새로운 코드 파일을 생성할 때는 반드시 다음을 수행해야 한다:

### 변경 이력 파일 생성
- `CHANGELOG.md` 파일에 다음 정보를 기록:
  - 생성 날짜와 시간
  - 새 파일을 만든 이유
  - 기존 파일이 필요없어진 이유 (해당시)
  - 새 파일에서 추가/변경된 기능
  - 기존 코드와의 차이점

### 새 파일 내 히스토리 주석
새로 생성하는 파일의 상단에 다음 형식으로 주석 추가:
```python
# File History:
# [YYYY-MM-DD HH:MM] Created: [생성 이유]
# [YYYY-MM-DD HH:MM] Modified: [수정 내용]
```

## 5. 코드 수정 시 히스토리 기록 의무
기존 파일을 수정할 때는 반드시 다음을 수행해야 한다:

### 파일 내 히스토리 주석 업데이트
수정하는 파일의 상단 주석에 변경 이력 추가:
```python
# File History:
# [YYYY-MM-DD HH:MM] Created: [초기 생성 목적]
# [YYYY-MM-DD HH:MM] Modified: [수정 내용 설명]
# [YYYY-MM-DD HH:MM] Modified: [또 다른 수정 내용]
```

### 주요 함수/기능 변경 시 인라인 주석
중요한 로직 변경 시 해당 부분에 주석 추가:
```python
# Modified [YYYY-MM-DD]: 새로운 파일 지원을 위해 파일명 변경
filename = 'Video_List_20250701-20250816_20250818041034.xlsx'
```

## 6. 예외 상황
다음의 경우에만 사전 허가 없이 새 파일을 생성할 수 있다:
- 설정 파일 (.json, .yml, .env 등)
- 문서 파일 (사용자가 명시적으로 요청한 경우)
- 임시 테스트 파일 (작업 완료 후 삭제 예정)
- 히스토리/로그 파일 (CHANGELOG.md, HISTORY.md 등)

## 7. 준수 사항
- 이 규칙은 모든 코드 작업에 적용된다
- 규칙을 위반하기 전에 사용자에게 확인을 받아야 한다
- 기존 코드의 품질과 일관성을 항상 우선시한다
- 모든 변경사항은 추적 가능해야 한다
